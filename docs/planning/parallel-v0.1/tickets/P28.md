# P28 内嵌 Skill 资源清单与读取导出

## Parent

[并行实施规格](../spec.md)；原始需求 [#32](https://github.com/CaiZongyuan/knowmesh/issues/32)。

## What to build

让用户仅凭后端 binary 就能发现、读取并导出与该版本一致的 Skill 及其引用资源。先交付真实可用的 knowmesh-shared 与资源分发能力，为 Loader、六个完整工作流和后端独立打包提供可验证输入。

## Acceptance criteria

- [ ] binary 在没有源码目录、Web 资源、Node.js 或已启动 HTTP 服务时仍可列出实际内嵌的 Skills，清单包含 name、version、description、required CLI range 与 content sha256。
- [ ] knowmesh-shared 使用当前可执行的 CLI 契约说明 workspace、JSON、写入确认、不可信来源和错误恢复；资源清单不把尚未交付的其余工作流呈现为完整可用。
- [ ] skills read 的 raw 输出与对应版本的 Markdown 字节及清单 hash 一致，普通元数据结果遵守 JSON 契约，日志不污染 stdout。
- [ ] 导出到显式目标目录后可以读取 Skill 及其完整引用资源；目录边界、现有不同内容和不可写目标得到明确处理，失败不会留下被宣称为完整的资源包。
- [ ] 未知名称、无效目标和资源缺失返回稳定 typed error；列表、读取和导出均通过公共命令发现机制注册。
- [ ] 资源内容变更会更新清单和快照；遗漏 Skill 或引用资源使嵌入完整性测试失败，移走源码后的独立 binary fixture 仍通过。

## Blocked by

None after approved shared baseline.

## Scope and handoff

本票拥有内嵌资源、清单、读取与导出能力及最小 shared Skill；复用 CLI envelope、命令注册与资源快照测试。公共命令注册是共享编辑点，变更应与并行命令工作协调。将版本化资源接口交给 P29、P30、P47；六个完整科研工作流由 P30 完成，Loader 目标路径选择由 P29 完成。
