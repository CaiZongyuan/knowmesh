# P42 在来源页面编译并恢复同一 Run

## Parent

[并行交付计划](../spec.md)；原任务 [#37](https://github.com/CaiZongyuan/knowmesh/issues/37)。

## What to build

用户在来源页选择可编译 revision，提交编译后观察阶段、累计预算和结果，并暂停、取消或恢复同一 Run。浏览器刷新、关闭后重开或短暂断线时，界面从后端任务状态恢复，不再次提交编译。

## Acceptance criteria

- [ ] 编译操作使用来源的实际质量状态与固定 revision，显示阻止编译的原因；一次明确提交只创建一个绑定幂等键的 Run。
- [ ] 页面通过生成客户端轮询 Run，显示 stage/progress、累计 usage/budget、输出引用、warnings 和 typed error；不以浏览器计时推算成功状态。
- [ ] 暂停、取消与恢复只显示服务端允许的动作；控制请求登记后展示等待停止状态，直到 Run 确认 paused/cancelled。
- [ ] 刷新、关闭重开或网络恢复后重新读取同一 Run；不自动重提 compile 或 resume，Server 遗留任务需要用户显式恢复。
- [ ] 同来源新 revision 的编译历史与当前 Run 可区分；成功结果显示实际 Proposal 引用，来源规范知识在 Apply 前不被改变。
- [ ] 浏览器测试覆盖提交、202 轮询、暂停/取消/恢复、预算错误、页面重开与断线；检查 provider 调用和 Run 身份证明没有重复任务，并通过契约漂移检查。

## Scope and handoff

本票拥有 Source 页的编译和任务控制体验。前置输入是 P41 稳定的 Run/compile HTTP、P35 的 revision 导航和 P37 的来源 mutation 约定。即使 Proposal 审核页尚未交付，也可通过真实 Proposal 输出引用独立验证成功；审核行为由 P38 提供。

共享热点是 Source 页面、Run 轮询 Query、状态恢复标识、生成客户端和浏览器任务 fixture。运行状态始终以服务器为准，临时 UI 不形成第二份 Run 状态机。P43 可复用任务呈现约定，但 Ask 输入、回答和保存操作不在本票范围。
