# P02: Proposal 列表与稳定分页

## Parent

[并行交付规格](../spec.md)；原任务 [#27](https://github.com/CaiZongyuan/knowmesh/issues/27)、[#31](https://github.com/CaiZongyuan/knowmesh/issues/31)。

## What to build

用户通过 `proposal list` 找到待审或历史 Proposal，取得有界摘要并继续分页；结果来自一致的 runtime 快照，随后可使用已有详情和审核操作。

## Acceptance criteria

- [ ] Core 定义列表输入、摘要输出和 Operation descriptor，CLI 映射同一用例；返回 ID、kind、revision、状态、来源/Run 引用与审核计数，不在列表加载完整 item payload。
- [ ] 状态等已声明筛选在分页前执行；默认有界，非法 limit/cursor 返回 typed error，排序在相同数据上稳定，数据与 envelope 均提供 continuation。
- [ ] 计数和当前页属于同一 SQLite 读事务；cursor 绑定 workspace、筛选和 runtime 结果版本，Proposal 审核改变而 canonical generation 不变时仍能识别过期页。
- [ ] 列表不保存恢复状态、不修改审核记录；已有 runtime 可读时，损坏的 Schema Pack 不妨碍查看摘要，缺少索引返回明确错误。
- [ ] 真实 workspace fixtures 覆盖分页、跨 workspace/query cursor、列表期间新增/审核/拒绝、空列表和损坏历史；已有 Proposal 读取与幂等测试保持通过。

## Blocked by

None (ready after approved shared baseline).

## Scope and handoff

Proposal read capability 拥有列表语义；复用基线 `5247efe` 的 revision storage、历史读取和 wire envelope。共享热点为 Proposal port、Operation registry、CLI 分派和 runtime 组装；与其他票协调增量注册即可，不因此添加业务依赖。交付列表到 CLI 的完整路径即停止；P03 负责组合 Apply，Run 列表由 P13 负责，现有幂等能力不重做。
