# P11: Entities 模式生成可审核 Proposal 规划

## Parent

[并行交付规格](../spec.md)；原任务 [#28](https://github.com/CaiZongyuan/knowmesh/issues/28)。

## What to build

从 P10 的来源候选出发，Compiler 核对实体 mentions，解析现有实体身份，并把新实体、alias/mention 等允许变化交给既有 Builder 形成可审核的 entities-mode Proposal 规划。

## Acceptance criteria

- [ ] Core 从真实候选产物与固定 revision 建立 entities 模式计划，验证临时引用、Schema 类型/属性和 mention 的来源定位；不可验证候选留下 warning，不变成有效知识。
- [ ] Entity Resolution 使用完整且一致的 Node catalog、Schema/hash 和实际检索上下文；唯一兼容 identifier/alias 可按既有规则关联，歧义、canonical name 或冲突身份保留 review。
- [ ] 可选模型 advice 使用已有闭合结果、prompt 与 usage；unknown/incompatible target 或截断不能静默选 Node，自动确定的关联不再调用 advice。
- [ ] 临时实体映射到现有或新规划身份后，Builder 生成 Schema 合法的 Node/mention 相关 items 与实际 before hashes；结果绑定 source revision、base generation、Schema 和知识上下文。
- [ ] 知识相关缓存绑定候选、query/filter、generation/实际 catalog、规则及模型 identity；同输入复用，索引或 Schema 改变时不能复用过期决策。
- [ ] 可执行集成测试以真实 workspace/SQLite catalog、P10 候选与 fake provider 验证新实体、唯一匹配、歧义、重复临时 ID、变化基线和无效 mention；Proposal 规划可预览，canonical 和 runtime 均无持久知识变化。

## Blocked by

- [P10: 可缓存的 Compiler 候选抽取](P10.md)。

## Scope and handoff

Compiler 拥有候选到 patch items 的映射；Entity Resolution 与 Proposal Builder 保持既有能力边界。复用 `entity_resolution`、entity advice、Evidence verifier 和只读 Builder，不重写 resolver/审核/幂等。共享热点为 compiler stage DTO、catalog snapshot identity 和候选映射。验收在最高 Core 集成用例，不增加临时公开命令；P12 扩展 assertions/full，P15 负责 source.compile registry/CLI、Run 和原子发布。停止于 entities Proposal 规划。
