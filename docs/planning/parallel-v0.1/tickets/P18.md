# P18: Source refresh 生成显式复核 Proposal

## Parent

[并行交付规格](../spec.md)；原任务 [#29](https://github.com/CaiZongyuan/knowmesh/issues/29)。

## What to build

用户对新版来源执行 `compile source --mode refresh`，比较该来源历史 Evidence 关联的 accepted assertions，得到追加证据、替代或冲突的显式 Proposal 与无法对应的复核 warnings。

## Acceptance criteria

- [ ] Refresh 扩展既有 source.compile Core DTO/descriptor/CLI，在 Run 准入时固定目标 revision；使用既有 source impact 找到历史依赖，比较范围可追踪到保存的知识快照。
- [ ] 与旧主张相同的内容可建议 append Evidence；新 Evidence 在目标 revision 上重新定位、验证并生成身份，即使 cache 或 embedding 可复用，也不沿用旧 revision 绑定。
- [ ] 改变、矛盾或可替代主张形成明确 reviewed items，无法对应的旧主张只记录 warning；新版未提及不自动 retract，来自其他来源的支持证据保留。
- [ ] Refresh 只持久化 Proposal/Run，旧 Claim/Relation/Synthesis 在显式审核 Apply 前不变；Apply 继续检查 current base generation、Schema 和 before hashes。
- [ ] Stage checkpoint、pause/cancel/resume、幂等和累计预算复用 P17，恢复依赖变化仍拒绝静默重跑；提交后重试返回原 Proposal。
- [ ] CLI/SQLite + fake provider fixtures 覆盖两来源共同支持、新版重述、矛盾、未再提及、soft-remove、retract/supersede 与 Synthesis 缺失快照；rebuild 后历史证据及 freshness/impact 保持一致。

## Blocked by

- [P17: 显式 Run resume 与崩溃、迟到结果恢复](P17.md)。

## Scope and handoff

Compiler refresh 拥有历史比较计划，复用 P12 的 assertion planning、P17 执行器和已有 source impact/freshness/Proposal Apply。共享热点为 compile mode、stage dependencies、历史 assertion read 和 registry Schema。停止于可恢复的 refresh Proposal 到显式 Apply 验收；P21 负责重新 Ask 后保存新 Synthesis，来源变更本身不覆盖既有综述或依赖快照。
