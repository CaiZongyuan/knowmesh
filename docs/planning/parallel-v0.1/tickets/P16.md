# P16: Run pause/cancel 与 CLI Ctrl-C

## Parent

[并行交付规格](../spec.md)；原任务 [#28](https://github.com/CaiZongyuan/knowmesh/issues/28)。

## What to build

用户在另一个 CLI 中暂停或取消正在编译的 Run，也可用 Ctrl-C 停止前台执行。控制请求持久化，执行器确认停止后才报告 paused/cancelled，仍可查询已产生的进度和费用。

## Acceptance criteria

- [ ] `run.pause/cancel` 使用 Core DTO、Operation descriptors、CLI 和现有 Run store；仅 source.compile/knowledge.ask 属于可恢复长任务，其他 operation 返回 RUN_NOT_RESUMABLE。
- [ ] Queued 未领取任务可直接停止；运行中先登记 control request，阶段边界及模型请求/重试等待期间检查，尝试中止网络，确认执行停止后才设置 paused/cancelled。
- [ ] 重复请求和同 key 重试无重复副作用；cancel 优先于 pause，终态与不允许的转换返回明确结果，allowed_actions 随持久状态准确变化。
- [ ] 被停止的 attempt 即使收到成功响应，也不能提交 stage、Proposal 或成功状态；已知 usage 仍结算，不确定计费保留预留，已有完整 checkpoint 可读。
- [ ] CLI Ctrl-C 持久化 cancelled checkpoint，stdout 为空，stderr 为 cancelled/RUN_CANCELLED envelope，退出码 130，details 含原 Run ID；无法落盘的强制退出保留供 P17 识别的状态。
- [ ] 可控 fake HTTP/provider 和真实 CLI subprocess fixtures 覆盖请求中停止、retry 等待中停止、queued 控制、重复控制、cancel 优先及取消后迟到响应；canonical 与未授权输出不变。

## Scope and handoff

Run control 用例拥有状态请求，执行器使用 P14 的逐请求控制边界，CLI 负责信号到同一 Core 用例的转换。共享热点为 Run state/allowed_actions、模型取消信号、CLI error/envelope 与 writer registry。停止于可靠暂停/取消和退出契约；P17 负责显式 resume、失联判定与跨进程恢复。Apply/rebuild 中断仍使用既有文件事务协议，不纳入长任务控制。
