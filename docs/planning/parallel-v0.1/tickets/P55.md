# P55 Sync、Doctor repair 与 Rebuild 的显式键重放

## Parent

[并行实施规格](../spec.md)；原始需求 [#14](https://github.com/CaiZongyuan/knowmesh/issues/14)、[#30](https://github.com/CaiZongyuan/knowmesh/issues/30)、[#31](https://github.com/CaiZongyuan/knowmesh/issues/31)。

## What to build

用户为 sync、doctor --repair 或 rebuild 指定显式幂等键后，即使响应丢失、再次执行或中途退出，也能取得同一次已提交维护操作的原始结果。补齐公共 CLI、Core 输入和持久回执，不以重复同步通常无变化或恢复可以多次执行代替键绑定与结果重放。

## Acceptance criteria

- [ ] 三个 Operation 的 Core Input、descriptor 与 CLI 均接受可选 idempotency key；无键保留原行为。键沿用基线的原字符串、非空、至多 256 UTF-8 bytes、无控制字符规则，普通只读 doctor 不因此变成写操作。
- [ ] 键按 workspace、operation 和版本化结构化输入指纹绑定；指纹覆盖同步选择、修复请求及 rebuild 的索引选择、discard-runtime、keep-backups 等实际语义。同键不同输入返回 IDEMPOTENCY_KEY_REUSED，相同输入返回首次已提交报告，不能改为当前诊断、最新 generation 或新的备份清单。
- [ ] 同键并发、提交后响应丢失与进程重新打开只形成一份有效操作结果；重复 rebuild 不再次替换索引、创建备份或执行清理，重复 repair 不重新解释已经完成的文件事务。未产生持久变更的输入校验失败不占用已提交键。
- [ ] 键、原始结果与 sync 的投影提交、repair 的文件恢复完成、rebuild 的候选替换分别具有明确的可恢复提交边界；真实进程在副作用提交与结果返回之间退出后，重试恢复同一回执或报告可诊断冲突，不能因当前数据库被替换而悄悄重新执行。
- [ ] dry-run 不创建键绑定、回执、备份或 staging，也不执行维护副作用；repair/rebuild 的实际调用即使命中旧键仍要求 yes，确认字段不用于绕过授权，预览与确认不会变成两次执行。
- [ ] 正常 rebuild/runtime 保留后仍可重放这些维护结果；显式 discard-runtime 的限制与本次操作回执归属明确，替换不能丢失正在完成的 rebuild 回执。已知绑定指向缺失、损坏或身份不匹配的回执时，不能从当前索引猜造首次结果；主动丢弃的历史 runtime 不宣称可从规范文件恢复。
- [ ] 真实 CLI、SQLite 与 subprocess fixtures 覆盖三个命令的同键重试、改变输入、并发、dry-run、确认、返回前退出、rebuild 替换与回执损坏；保持原有缺失索引处理、恢复冲突、备份和 JSON stdout/error 契约，并同步公共契约说明。

## Blocked by

None after approved shared baseline.

## Scope and handoff

本票拥有三个维护 Operation 的显式键输入、持久结果、恢复协调与 CLI 接入，复用固定基线的 sync、Doctor repair、原子 rebuild、文件事务和键验证经验。Proposal 的专属请求指纹和 revision 引用不直接充当维护报告格式；每个操作应明确自身结果身份与提交边界。

共享热点是维护 Core 输入/输出、Operation registry、CLI、runtime 回执和重建保留、迁移编号及架构写入口。与真实故障矩阵 P27 协调恢复接口，但可从已实现维护能力独立验证。P37 在本票完成后映射 sync 的 HTTP 输入，P54 消费完整键重放证据；初始化前尚无 workspace/数据库的情形由 P56 单独负责，本票不建立新的通用任务执行器。
