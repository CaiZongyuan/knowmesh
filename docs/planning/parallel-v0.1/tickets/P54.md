# P54 Release candidate 完整性与独立安装验收

## Parent

[并行实施规格](../spec.md)；原始需求 [#1](https://github.com/CaiZongyuan/knowmesh/issues/1)、[#31](https://github.com/CaiZongyuan/knowmesh/issues/31)、[#43](https://github.com/CaiZongyuan/knowmesh/issues/43)、[#44](https://github.com/CaiZongyuan/knowmesh/issues/44)、[#45](https://github.com/CaiZongyuan/knowmesh/issues/45)。

## What to build

对固定版本的最终后端、npm 与 Web 候选产物完成 v0.1 完整性、独立安装和兼容性验收，形成可以直接审查的 release candidate 报告。发现缺失行为时形成范围明确的后续修复，不把验收票变成未定义的补全项目。

## Acceptance criteria

- [ ] 固定 integration commit、后端/Web/API 版本、artifact checksum 和依赖票证据，逐项核对 SPEC 第 25 节以及完整命令树；所有直接与传递交付项都有通过、失败或未验证状态。
- [ ] 用最终原生候选包在三大 OS 验证 headless 流程，覆盖五目标产物清单、安装器与校验；全新无 Web/Node.js 环境记录十分钟内 init 到 search 体验，并通过固定模型 adapter 的 init、add、compile、review、apply、search、evidence 完整闭环。
- [ ] 最终 npm/npx 候选包与原生执行的 JSON、cwd、argv、stdin/stdout/stderr、退出码及 compile/ask 中断行为一致；安装、升级、卸载不修改规范知识，后端安装没有 Web 下载或前端依赖。
- [ ] 最终 Web 候选包独立解压挂载后通过 SPEC 22.7 主流程、API-only、移除 Web、兼容/不兼容组合和分别升级验收；检查版本握手、生成客户端 drift、键盘与列表替代交互，并记录 localhost warm 首屏小于 2 s 的实际结果。
- [ ] 汇总迁移、rebuild 不变量、真实进程故障恢复、Run/预算/幂等、刷新历史、无密钥降级和六个 Skills 的真实 Harness 证据；绿色子集测试不替代完整 gate。
- [ ] P51 的至少 20 个人工 gold 片段、100% Proposal assertion locator validity，P52 的检索基线与性能报告，以及 P53 的至少 10 个真实问题人工事实支持评审均有可复查结果；失败和未验证项保留并阻止被宣布为全部通过。
- [ ] 报告列出 release notes、安装升级说明、支持边界与非临床生产/非多用户说明；发现遗漏时分配带验收条件的后续修复并保持候选未通过。本票不关闭或修改父 issue #1，生产 tag、release 和 npm 发布仅在候选通过且用户明确授权具体发布后执行。

## Scope and handoff

本票拥有最终候选的验收报告与发布资格结论，复用所有已交付模块、发布工作流和评测证据；不重新实现它们。报告可引用整个传递依赖闭包以查找遗漏，缺失能力仍需独立明确范围。公共文档、版本与兼容声明由集成人协调更新；生产发布是候选通过后的独立授权动作，不把发布成功设为构建工作流 P50 的前置条件。
