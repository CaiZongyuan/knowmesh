# P21: 原始 Ask 快照到 Synthesis Proposal 保存闭环

## Parent

[并行交付规格](../spec.md)；原任务 [#10](https://github.com/CaiZongyuan/knowmesh/issues/10)、[#41](https://github.com/CaiZongyuan/knowmesh/issues/41)。

## What to build

用户选择已有 Ask Run 创建 Synthesis Proposal，经现有 review/apply 保存为规范 Markdown；生成时真正使用的依赖快照随之固定，之后可以再次检索并识别变化。

## Acceptance criteria

- [ ] `synthesis.propose` 具备 Core Input/Output、Operation descriptor、CLI、dry-run 与幂等 key；只接受存在且可保存的已验证 Ask result，失败/取消或非 Ask Run 返回明确错误。
- [ ] 从原 Run bundle/结果复制实际 Evidence IDs、assertion 语义 hash 和生成时 source heads；current index 用于新 Proposal 的基线验证，不重构或替换历史依赖快照。
- [ ] 引用和依赖继续通过已有 Builder/Schema/Evidence 校验；缺少原 manifest、引用被篡改或依赖不存在时阻止创建有效 Proposal，partial 答案保留其停止原因、缺口和限制。
- [ ] dry-run 不写 runtime/canonical；同 key 重试返回同一 Proposal，实际保存仍经过已有 review/accepted subset/Apply transaction，不绕过人工 policy 或 before hash。
- [ ] Apply 后新 Synthesis 可经 Search 检索和继续解析原 Evidence；来源或 assertion 后续变化产生 freshness 原因，删除 DB 后重建同样成立。
- [ ] CLI/SQLite fixtures 覆盖 Ask 后来源换版再 propose、旧快照缺失、伪造引用、幂等重试与重新 Ask 保存；重新生成创建新 Synthesis 并保留旧正文/快照，已有 parser round-trip 继续通过。

## Blocked by

- [P20: 持久且有证据约束的 Ask](P20.md)。

## Scope and handoff

Synthesis propose 用例负责从可信 Run 产物构造 Proposal；复用已完成的 Synthesis parser/writer、Builder/Apply、freshness 和 Search。共享热点是 Ask result/manifest contract、Proposal origin/run 绑定和 registry/CLI；原 #10 剩余的 Ask snapshot 责任在本票完成，parser 不重做。停止于保存、检索、重建闭环；P06 的读取和 Web 保存控件各自独立，自动覆盖旧综述不属于 v0.1。
