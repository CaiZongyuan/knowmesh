# P19: 确定性 Evidence bundle 与可见省略清单

## Parent

[并行交付规格](../spec.md)；原任务 [#40](https://github.com/CaiZongyuan/knowmesh/issues/40)。

## What to build

Core 从实际过滤后的检索命中构建模型将看到的 Evidence bundle，保留完整 quote、冲突双方和来源/预算限制。产物包含可重复验证的 manifest，后续回答只能引用实际保留的 Evidence IDs。

## Acceptance criteria

- [ ] 最高 Core 用例连接真实 lexical Search 与 P05 一致快照读取，将 Claim/Relation 命中解析为原始 Evidence，Synthesis 命中回溯其 Evidence；只有原始 Chunk 时返回缺口，不创造 Evidence ID。
- [ ] 按 revision、定位区间与 quote hash 去重，同 revision 的重叠上下文只发送一次但保留全部相关 ID/完整 quote/locator/assertion 关联；跨 Source/Revision 保持身份独立。
- [ ] 命中 conflict group 时补取 filters 内双方并优先各保留一条；filtered_out/unavailable/budget 导致缺少一方时在 conflicts 与 omitted 中披露，source/evidence/token/cost 硬上限始终有效。
- [ ] 默认 max_sources=12、max_evidence=30、max_source_share=0.5，范围符合 SPEC；按检索排名和 Evidence ID 稳定选择，来源占比仅因允许例外放宽并记录原因，不补低相关证据凑数。
- [ ] 扣除 prompt/Schema/Purpose/问题/预留输出后计算输入预算；quote 保持完整，附加上下文沿自然边界裁剪并标记两端截断，放不下整条 quote 时省略且原因可见。
- [ ] Manifest 保存最终 IDs、Source counts、assertion 语义 hash/source heads、context hash、截断、token 估计、去重映射、omitted 与 freshness；真实 SQLite 集成 fixtures 覆盖重叠、镜像、单来源、表格、冲突双方不足预算、stale 依赖和 Chunk-only。

## Blocked by

- [P05: Claim、Relation 与 Evidence 读取闭环](P05.md)。

## Scope and handoff

Ask bundle capability 拥有确定性证据选择与 manifest；复用 Search/freshness/canonical citation 信息和 P05 的批量快照契约。共享热点是 evidence read DTO、预算输入和 manifest identity，需向 P20 交付最终允许引用的确切集合。此票通过真实 Core/SQLite 集成用例验收，不新增公开 bundle 命令；P20 负责 knowledge.ask registry/CLI、模型和敏感 Run 产物持久化。停止于模型输入 bundle，无需等待 vector、Compiler 或 Graph UI。
