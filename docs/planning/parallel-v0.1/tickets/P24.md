# P24: CLI 列表格式与 NDJSON 输出契约

## Parent

[并行交付规格](../spec.md)；原任务 [#30](https://github.com/CaiZongyuan/knowmesh/issues/30)。

## What to build

用户对适用的列表结果选择 table/csv，对已声明的流式或批量结果选择 ndjson；默认 JSON 和 pretty 保持已有 envelope 契约，机器读取不会混入日志或交互问题。

## Acceptance criteria

- [ ] 在合入时所有已登记的适用列表上交付 table/csv 和适用 ndjson 的完整 CLI 行为，至少覆盖已有 Source list，明确支持命令及列字段；Core 用例/DTO 不随渲染格式改变，新增列表可复用同一支持规则。
- [ ] Table/csv 仅用于声明的扁平列表，包含 Unicode、引号、逗号、换行、空值和空列表时格式仍可解析；不支持的嵌套/detail 命令返回稳定 validation error。
- [ ] NDJSON 每行是一个完整 JSON object；records、continuation/partial metadata 和结束/错误表达有固定合同，正常结果不会拆成半个 JSON 或混入进度日志。
- [ ] JSON/pretty、typed stderr、非零退出码及 source.content raw 例外保持兼容；raw 与任何显式 format 仍冲突，参数顺序不改变结果。
- [ ] 分页下一页信息在支持的机器格式中可获得；输出格式不会造成隐式查询更多页、额外写入或丢失未知字段而假装完整。
- [ ] Shell contract fixtures 覆盖每种支持格式、unsupported format/command、stdout/stderr 分离和 piping；help、schema command 的公共输入/输出说明与实际能力一致。

## Blocked by

None (ready after approved shared baseline).

## Scope and handoff

CLI renderer 拥有格式与终端输出，复用已有 wire envelope、Source list 和 raw contract；不把格式分支放进业务用例。共享热点为全局 CLI 参数、formatter、error path 和 command capability 声明；与 P25 协调同一区域。P24 负责接入其合入前已经存在的适用列表；P02/P04-P06/P13 等若之后合入，则随各票声明格式支持并运行共享渲染合同，不因落地顺序遗漏接入。compile/ask 的单最终 envelope 不能因 ndjson 选项被改为未经约定的进度流。
