# P30 六个完整版本化 Skills 与可执行示例

## Parent

[并行实施规格](../spec.md)；原始需求 [#32](https://github.com/CaiZongyuan/knowmesh/issues/32)。

## What to build

以已交付命令为依据，完成 shared、search、research、ingest、graph、maintain 六个内嵌 Skills。每个 Skill 提供可执行的完整流程、写入边界和错误恢复，Agent 可直接使用当前 binary 的版本化内容完成任务。

## Acceptance criteria

- [ ] 六个 Skills 均完整出现在资源清单中，版本、兼容 CLI 范围、内容 hash 和引用资源一致，不保留被当作完整工作流发布的占位内容。
- [ ] 每个 Skill 包含触发和非触发条件、shared 前置规则、3 至 7 步主流程、read/write 区分、dry-run 与人工确认时机、typed error 恢复以及不可信内容规则。
- [ ] 每个 Skill 至少有两个完整 CLI 示例和对应集成任务；实际执行或契约 fixture 验证命令、参数、结果字段及后续步骤，示例不调用尚未实现的命令。
- [ ] search、graph、research 覆盖检索、ID 解析、节点或断言、关系路径和原始 Evidence；研究流程保留冲突与知识缺口，并说明保存 Synthesis 所需的 Proposal 审核。
- [ ] ingest 流程从来源导入到检查、compile 和 Proposal 审核，清楚区分生成候选与显式 Apply；maintain 流程覆盖 status、doctor、sync、rebuild 与 migrate 的预览和确认。
- [ ] 未解析 ID、陈旧 Proposal、不可恢复或输入变化的 Run、无模型密钥及可选能力缺失均有可执行恢复分支；流程无法继续时保留真实状态，不伪造结果。
- [ ] 嵌入快照和引用检查通过，用户文档与示例从同一命令契约取事实；技能文档更新不改动业务语义。

## Scope and handoff

本票拥有面向产品用户的六个 Skill 工作流与示例，复用已完成命令和 P28 的资源分发；主要编辑文档与任务 fixture。资源清单和嵌入快照需协调更新。若示例暴露缺失能力，交给该能力的票修复再继续，不能在 easy 票中隐含建设 Compiler、Graph 或迁移系统。P31 使用这些 Skills 进行真实 Harness 验证。
