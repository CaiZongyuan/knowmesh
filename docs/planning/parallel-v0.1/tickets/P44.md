# P44 只读查看设置、Schema、模型能力与诊断

## Parent

[并行交付计划](../spec.md)；原任务 [#34](https://github.com/CaiZongyuan/knowmesh/issues/34)、[#36](https://github.com/CaiZongyuan/knowmesh/issues/36)。

## What to build

补齐 SPEC 已列出的设置与诊断路由：用户只读查看 workspace 配置摘要、Schema Pack、模型 profile/能力及现有 doctor 诊断。本票的只读范围已批准，新增的最小 HTTP 读取契约必须同步到公共规格；不增加设置编辑、密钥写入或自动修复。

## Acceptance criteria

- [ ] 设置、Schema、模型与诊断页面均读取真实后端数据；settings 映射 settings.get，diagnostics 映射只读 doctor，未配置或不可用项明确显示状态。
- [ ] Schema 页面展示已配置 Pack、版本和验证结果，并接通既有 schema.pack/schema.command 读取契约；无效配置有 typed error，不自动改变 Pack、迁移知识或创建 workspace。
- [ ] 模型页面显示 profile、声明能力和可确认的配置就绪状态；不能把未执行的远程调用宣称为验证成功，也不为打开页面消耗模型预算。
- [ ] HTTP、页面、日志及错误详情均不包含解析后的密钥、长期 token 或其他敏感配置；脱敏检查覆盖成功和失败响应。
- [ ] 诊断页面复用现有只读 doctor 结果，呈现真实问题、恢复建议和能力限制；读取不修复事务、不重建数据库、不修改配置。
- [ ] 新增读取 Operation、HTTP 路由、OpenAPI 和生成客户端同步登记；浏览器测试覆盖健康、缺配置、配置错误、权限拒绝与脱敏，界面不提供未实现 mutation。

## Blocked by

- [P33 Web 状态页与生成客户端](P33.md)

## Scope and handoff

本票拥有只读 settings.get、doctor 和 schema.pack/schema.command 的 HTTP 与页面。前置输入是现有配置加载、Schema Pack、status/capabilities 与 doctor；settings 摘要列出已配置 Pack 身份，读取详情无需新增全局 Schema 列表端点。交付前核对共享规划中的读取命名和字段，不从页面直接读取文件或数据库。诊断只展示当前已验证能力，不要求其他 doctor 深化票先完成。

共享热点是安全配置摘要 DTO、Operation registry、HTTP/OpenAPI、生成客户端和设置路由。schema.entity HTTP 由 P34 交付，schema.patch HTTP 由 P38 交付，本票不重做也不依赖它们。所有新增事实以公共契约为唯一来源。配置编辑、模型连通性测试、密钥安装、迁移和修复执行均是后续独立范围；本票不把这些功能偷偷加入只读页面。
