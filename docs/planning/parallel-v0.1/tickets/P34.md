# P34 贯通搜索到知识与原始证据的浏览流程

## Parent

[并行交付计划](../spec.md)；原任务 [#34](https://github.com/CaiZongyuan/knowmesh/issues/34)、[#37](https://github.com/CaiZongyuan/knowmesh/issues/37)。

## What to build

用户在 Web 搜索现有知识，打开 Node、Claim 或 Relation，并检查其引用 Evidence 的原始 quote、来源 revision 与 locator。一次交付所需 HTTP 读取操作、生成客户端及页面，复用现有检索和前置知识读取 Core。

## Acceptance criteria

- [ ] HTTP 搜索及 node、claim、relation、evidence、schema.entity 读取映射至同一 Core；Relation 采用已确认的列表/单条端点，响应、错误、过滤和分页与 CLI 一致，并同步 OpenAPI 及生成客户端。
- [ ] 搜索结果按实际记录类型分组，显示命中原因；开启 explain 时可查看真实通道排名，未接通的 Graph path 等类型不得伪造结果。
- [ ] 搜索与筛选状态可由 URL 恢复，翻页按游标读取；query mismatch 或 stale cursor 有明确重新查询流程，不混合不同快照结果。
- [ ] 从结果进入 Node 阅读与 Inspector 后，可继续查看关联 Claim/Relation 和全部 Evidence，展示 quote、source、固定 revision、locator 与可用 freshness 信息。
- [ ] 原始内容作为不可信数据渲染，Markdown 不执行原始 HTML 或脚本；不可用记录、无证据和空结果均有明确状态。
- [ ] 浏览器测试覆盖搜索到知识再到 Evidence 的完整路径、错误与键盘操作；请求来自生成客户端，服务器数据不复制到第二份 UI 缓存。

## Scope and handoff

本票拥有知识检索与证据 Inspector 的首个浏览闭环。前置输入是 P04/P05 的稳定读取 DTO、P33 的握手与缓存约定，以及已实现的 Search Core。来源全文和 page/section 内容导航由 P35 补齐；本票可独立以完整 quote 与 locator 验证证据可追溯。

共享热点是公共 HTTP 路由登记、OpenAPI 快照、生成客户端、共享 Inspector 与路由树。先合并前置契约，再集中再生成客户端；新增生成物不手工解决冲突。本票独占 schema.entity HTTP 的交付，P44 无须等待该接口；后续 Graph、Proposal 和 Ask 复用本票 Evidence 展示。Graph paths 由 P39 接通，Synthesis list/get HTTP 与专页由 P43 交付。
