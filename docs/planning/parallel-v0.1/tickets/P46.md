# P46 安全托管独立 Web 资源并验证兼容性

## Parent

[并行交付计划](../spec.md)；原任务 [#44](https://github.com/CaiZongyuan/knowmesh/issues/44)。

## What to build

用户显式指定已下载的外部 Web 目录后，Server 验证资源结构与 API 兼容性并提供同源静态页面。用最小静态 fixture 即可独立验证托管、安全边界和缓存语义，不等待完整 Web 产品或发布流水线。

## Acceptance criteria

- [ ] 未指定 web-dir 时保持 API-only；指定后按当前工作目录解析相对路径，读取独立目录中的入口与 manifest，不主动下载或发现 Web。
- [ ] 目录、入口或 manifest 缺失/无效时返回 `WEB_ASSETS_INVALID`；API range 或 required capabilities 不满足时返回 `WEB_API_INCOMPATIBLE`，不静默降级启动。
- [ ] 静态目录和 workspace 不得互相包含；路径穿越、编码绕过、隐藏文件、目录列表及 symlink 逃逸均不能读取边界外内容。
- [ ] SPA fallback 只处理页面导航；不存在的 API、静态资源和 manifest 请求保持 404，不能返回伪装成成功的入口 HTML。
- [ ] hash assets 使用长期缓存，入口与 manifest 使用 no-cache；替换到兼容的新 Web 目录后可加载新版本，认证规则仍由既有 Server 统一执行。
- [ ] 不兼容 Web 被拒绝或移除 Web 后，普通 CLI 仍可运行；托管、切换目录和资源失败均不修改规范知识或自动触发迁移。
- [ ] HTTP 测试以真实临时静态目录覆盖有效资源、兼容/不兼容 manifest、安全边界、缓存和 404；无需前端构建工具即可运行后端托管测试。

## Blocked by

- [P32 API-only Server](P32.md)

## Scope and handoff

本票拥有外部静态资源解析、manifest 检查和 HTTP 托管。前置输入是 P32 的 API contract version、实际能力和认证方式；测试 manifest 只要求 fixture 所需的已实现能力，不虚构 graph 可用性。

共享热点是 serve 参数、Server 路由边界、manifest DTO、错误映射和静态托管依赖。资源根目录与知识 workspace 的路径规则有不同目的，不能复用为同一种包含校验。交付测试 manifest、目录结构和缓存契约供后续 Web 打包票使用；实际 Web 构建、压缩包、checksums、发布和完整浏览器兼容验收不在本票范围。
