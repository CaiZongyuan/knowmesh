# P32 启动具备安全边界的 API-only Server

## Parent

[并行交付计划](../spec.md)；原任务 [#34](https://github.com/CaiZongyuan/knowmesh/issues/34)。

## What to build

用户仅安装后端即可启动 HTTP 服务，查看存活状态、workspace 状态和 API 能力。建立后续业务路由复用的请求认证、错误映射、Operation 登记与基础 OpenAPI 契约；该票不要求任何 Web 包或其他业务路由已实现。

## Acceptance criteria

- [ ] 默认仅绑定 loopback；没有 Web 资源时正常启动，健康检查不触发模型调用或数据库重建，首页返回 404。
- [ ] capabilities 返回独立的后端版本、API contract version 和实际 workspace 能力；尚未实现或不可用的能力不得宣称为可用。
- [ ] status 通过现有 Application Core 返回 workspace 状态；成功及失败 envelope、trace 与 HTTP status 使用共享契约，Adapter 不直接读取数据库。
- [ ] 非 loopback 绑定必须同时显式允许远程访问并提供 token 环境变量；无授权请求被拒绝，长期 token 不进入响应、日志或静态资源。
- [ ] 默认关闭 CORS，开发 origin 使用明确允许列表；建立 bearer token 或 loopback session nonce 校验，协议级测试证明无效身份或不允许的 origin 不能通过 mutation 防护。
- [ ] 基础 OpenAPI 3.1 可读取并形成可重复生成的快照；实际业务路由有登记的 Operation，健康检查等传输路由有明确例外，未登记业务路由触发合同检查失败。
- [ ] API-only 启停、端口占用、安全拒绝及 typed error 有真实 HTTP 合同测试；后端构建和启动不需要前端工具链。

## Blocked by

None；共享基线合并后可开始。

## Scope and handoff

本票拥有 Server 启停、安全边界和最小可观测 API。前置输入是已实现的 status、版本、能力、错误映射与 Operation registry；若能力尚无公共 DTO，在本票形成最小共享契约。

共享热点是 Rust 依赖清单与锁文件、CLI 命令登记、Operation registry、架构规则和 OpenAPI 快照。开始前登记这些文件的写入窗口；只导出本票实际服务的操作，不为后续业务生成虚假可用端点。后续票扩展独立路由并复用本票安全检查；Web 托管、任务执行、watcher 和完整 HTTP 命令面分别由其所属票完成。
