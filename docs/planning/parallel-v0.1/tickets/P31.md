# P31 全新上下文 Harness 读写 smoke 验证

## Parent

[并行实施规格](../spec.md)；原始需求 [#33](https://github.com/CaiZongyuan/knowmesh/issues/33)。

## What to build

在 Claude Code、Codex 与 generic shell Agent 的全新上下文中验证仅靠 Loader 和后端 CLI 能完成证据检索与受控写入。保存真实执行记录，让 Harness 集成结论与命令脚本测试可明确区分。

## Acceptance criteria

- [ ] 三类 Harness 各自记录实际版本、模型或执行配置、后端版本、Loader hash、任务输入、执行轨迹和结果；只给 Loader、任务和 fixture workspace，不预先注入完整 Skills 或仓库实现。
- [ ] 每类 Harness 实际完成 search 到 ID 解析、节点或断言、关系查询和 Evidence 读取，结果能追溯到 fixture 的不可变 Source Revision。
- [ ] 每类 Harness 实际完成 source add、inspect、compile 和 Proposal 检查；未经确认不 Apply，经任务明确授权后才完成审核与 Apply，并可读取变更结果。
- [ ] 至少一个实际任务经历中断后的 run inspect/resume，沿用同一 Run 且不重复发布 Proposal；恢复决策来自公开 allowed_actions 和 typed error。
- [ ] 任务含不可信来源指令和写入诱导，执行记录显示来源只被当作数据；测试只操作独立 fixture workspace，模型步骤可使用明确标识的固定 adapter fixture。
- [ ] 对成功、失败和未验证分别保存证据；缺少 Harness、登录、可用模型或执行权限时登记外部前提并保持相关验收未完成，脚本或模拟记录不代替真实 Harness 结果。

## Scope and handoff

本票拥有实际 Harness smoke 任务和执行证据，复用 Loader、六个 Skills、Run 恢复和现有隔离 fixture。真实 Harness 的可用性是代码依赖之外的就绪条件。发现 Skill 问题交给 P30，公共命令问题交给能力所有者；本票不扩展第三方 Harness。P54 以真实通过记录判断 Agent 验收。
