# P17: 显式 Run resume 与崩溃、迟到结果恢复

## Parent

[并行交付规格](../spec.md)；原任务 [#28](https://github.com/CaiZongyuan/knowmesh/issues/28)。

## What to build

用户显式 `run resume`，在同一 Run 身份上从最近完整且依赖仍有效的 checkpoint 继续。并发恢复、进程退出、缓存丢失和迟到成功都保持单一有效执行者与一次本地输出发布。

## Acceptance criteria

- [ ] `run.resume` 提供 Core DTO、descriptor、幂等 key 和前台 CLI；遵循 allowed_actions，paused/interrupted/cancelled/retryable failed 可恢复，succeeded/partial 和非 retryable failed 不恢复。
- [ ] 取得 OS lock 并复查 SQLite 后，才把无主 running 判为 interrupted 并领取新 attempt；同时 resume 只有一个有效领取，get/list、执行器重启或页面刷新均不自动消费 queued/interrupted 预算。
- [ ] 恢复验证原 Input、revision bytes、prompt/Schema/Purpose/provider semantics 和每次模型实际知识快照；依赖不可用或变化返回 RUN_INPUT_CHANGED 并保留旧 Run，只有 secret 轮换且语义不变可继续。
- [ ] 验证 checkpoint 指向的完整 immutable artifacts；丢失/损坏时从最早缺失阶段重算，已验证成功产物避免重复调用，累计请求/repair/retry/tokens/cost/执行 timeout 不清零。
- [ ] 旧 attempt 和取消后的晚到结果无法发布 checkpoint/Proposal/Answer；已知计费按原请求记录，最终输出已提交时直接返回同一 output refs，不再建 Proposal。
- [ ] 真实进程强制退出、并发 resume、输出提交后响应丢失和 fake provider 迟到 fixtures 覆盖完整 §22.9 任务恢复矩阵；断言本地只发布一次、控制/预算可恢复，远端计费不作 exactly-once 承诺。

## Blocked by

- [P16: Run pause/cancel 与 CLI Ctrl-C](P16.md)。

## Scope and handoff

Run recovery 拥有失联判定、依赖恢复和新 attempt 领取；复用 P13–P16 的 input、request ledger、OS ownership、checkpoint 与 publication transaction。共享热点为 executor stage contract、runtime copy、Run CLI 和 cache validation。停止于 compile 的完整控制/恢复矩阵，并交付给 P20/HTTP 复用；P18 引入 refresh stage，独立 daemon、自动调度和多 workspace 队列均不在 v0.1。
