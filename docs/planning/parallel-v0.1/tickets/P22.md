# P22: Embedding provider 与按输入复用的缓存

## Parent

[并行交付规格](../spec.md)；原任务 [#18](https://github.com/CaiZongyuan/knowmesh/issues/18)。

## What to build

Core 对明确的实际文本输入调用配置的 embedding provider，取得受验证的向量并复用完整缓存。内容相同而位置不同的来源输入可复用向量，profile 或实际输入变化则不能复用。

## Acceptance criteria

- [ ] Embedding port/Core 用例与真实 provider adapter 贯通，使用已有 workspace embedding 配置和环境变量 secret 解析；请求/响应规模与 timeout 有界，错误和日志不包含 secret 或原文。
- [ ] Active profile identity 覆盖 provider/model/dimensions、预处理与配置；返回数量、顺序关联、维度和有限数值被验证，错配向量不能保存为成功产物。
- [ ] Cache key 使用实际发送文本 hash 和 profile；发送标题或其他上下文时一并计入，不以 Chunk ordinal、路径或 locator 作为向量身份。
- [ ] 相同文本在新 revision/不同位置可命中同一向量产物；输入、模型、维度或 profile 变化导致 miss，损坏/丢失产物重新计算，真实 I/O 错误不伪装成 miss。
- [ ] Provider 未配置、缺 key 或暂不可用时返回可判定的 unavailable 信息，调用方可维持 lexical 能力；embedding 不写 canonical，不改变 Evidence/Revision 身份。
- [ ] 可执行 Core/adapter 集成测试使用现有 Chunk/文本 fixture、真实缓存与本地 fake HTTP provider，覆盖输入复用、语义 profile 变化、错误响应、损坏产物和无 key；不依赖 P09 已完成索引。

## Blocked by

None (ready after approved shared baseline).

## Scope and handoff

Embedding capability 拥有 provider、输入/profile identity 与缓存验证；复用既有 StageKey/FileStageCache、workspace secret/config 规则。共享热点是 Embedding port、provider 组装和配置 Schema；通过最高 Core 用例集成测试验收，不新增临时 embedding CLI。P23 负责把向量接入现有 Search/registry 输出及独立索引映射，并依赖 P09 的可索引 Chunk。停止于可验证的向量产物，不实现 sqlite-vec 或静默改变 Search ranking。
