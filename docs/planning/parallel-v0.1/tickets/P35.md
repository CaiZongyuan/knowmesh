# P35 浏览来源历史内容与分页影响清单

## Parent

[并行交付计划](../spec.md)；原任务 [#34](https://github.com/CaiZongyuan/knowmesh/issues/34)、[#37](https://github.com/CaiZongyuan/knowmesh/issues/37)。

## What to build

用户通过 Web 查阅来源 metadata、全部 revision、解析内容和更新影响，按页或章节定位当前及历史证据。交付来源读取 HTTP、生成客户端和 Source 页面；读取不创建编译任务或修改来源。

## Acceptance criteria

- [ ] 来源列表、详情、解析上下文和 impact 的 HTTP 操作复用已有 Core 与 P09 产物；当前与历史正文分别使用 sources/{id}/content 和 source-revisions/{id}/content，均调用 source.content，并同步 OpenAPI 与生成客户端。
- [ ] Source 页面显示当前 head、revision 历史、hash、文本编码、来源状态和已知解析质量；未解析、needs_ocr 或 blocked 的材料有明确状态，不自动启动模型。
- [ ] 按 page/section 或 Evidence locator 可定位正确 revision 的内容；受管及 referenced 内容读取仍校验大小与 hash，底层内容变化返回真实错误。
- [ ] 新 revision 和 soft-remove 后仍可打开历史 revision；页面不能把旧证据定位到最新来源内容，也不能把未有快照的 Synthesis 当成 fresh。
- [ ] impact 列表按真实游标分页，展示受影响 assertion/Synthesis、freshness 原因与 generation；stale cursor 明确重载，不静默混合版本。
- [ ] 浏览器测试覆盖历史证据定位、正文或 PDF 的实际呈现、质量失败状态、来源更新影响和分页；来源文本中的脚本或 HTML 不可执行。

## Scope and handoff

本票拥有只读 Source 页面与上下文 API。前置输入包括已实现的 Source list/get/content/impact、不可变 revision 规则和 P09 解析结果读取方式；读取已有产物的能力不足时在本票补齐最小只读契约，不引入新的 Compiler。

共享热点是 HTTP 路由与鉴权、OpenAPI 快照、生成客户端、内容定位组件及路由树。后续 P37 增加来源写操作，P42 增加 Run 控制；本票留下稳定的 revision/locator 导航输入，不提前显示可执行的编译按钮。与其他表面票协调契约再生成窗口。
