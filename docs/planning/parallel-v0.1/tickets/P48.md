# P48 npm 后端下载器与透明命令启动器

## Parent

[并行实施规格](../spec.md)；原始需求 [#43](https://github.com/CaiZongyuan/knowmesh/issues/43)。

## What to build

把现有 npm 初始化占位包升级为可测试的后端安装渠道，按平台下载同版本原生 artifact 并透传 CLI 进程行为。npm 和 npx 用户获得与原生安装相同的后端能力，Web 保持独立安装。

## Acceptance criteria

- [ ] 候选 npm 包按当前平台选择 P47 的同版本后端 artifact，校验下载内容；本地安装与 npx 候选包测试使用受控 artifact 来源，不发布生产 npm 版本。
- [ ] 启动器保留 cwd、argv 和 stdin/stdout/stderr，包含带空格路径、Unicode 参数、标准输入 JSON、原始字节输出和非零退出码的对照测试与原生执行一致。
- [ ] 中断信号传到子进程，启动器退出后不遗留后端进程；已有受控取消 fixture 验证可观察行为，最终 compile/ask 取消语义交给 P54 复验。
- [ ] 安装进度和下载诊断不进入后端命令的 JSON stdout；下载失败、checksum 不匹配、离线缺缓存和不支持平台均给出明确失败结果。
- [ ] 包内容、依赖与下载请求检查证明不会安装前端依赖或访问 Web 发布资源，不在用户机器自动编译后端或安装额外 runtime。
- [ ] 使用可核验的本地候选包完成安装、执行、卸载与升级 fixture；知识 workspace 保持不变，文档说明 npm 渠道的 Node.js 前提以及 npx 与长期 PATH 安装的区别。

## Blocked by

## Scope and handoff

本票拥有 npm 包的下载与进程启动行为，复用原生 artifact 和 checksum；与 P47 协调平台映射，与 P50 协调包版本及发布清单。现有 bootstrap 发布流程不能当作完整 CLI 分发验收。P50 再接入发布顺序，P54 检查最终候选版本的完整命令行为。
