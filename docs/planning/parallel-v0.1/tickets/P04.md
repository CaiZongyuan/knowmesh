# P04: Node get/list 与 Schema entity discovery

## Parent

[并行交付规格](../spec.md)；原任务 [#31](https://github.com/CaiZongyuan/knowmesh/issues/31)。

## What to build

用户和 Agent 可按 Node ID 或名称查看知识节点，按类型等声明筛选分页浏览，并通过 `schema entity` 取得其类型、属性约束与展示 metadata。

## Acceptance criteria

- [ ] `node.get/list` 和 `schema.entity` 具备 Core DTO、Operation descriptors 与 CLI 映射；Node detail 返回规范 metadata、摘要和已记录关联，列表返回有界摘要。
- [ ] ID 精确读取；名称存在多个候选时返回可判定的 ambiguity，而不静默选取；不存在对象、类型或非法输入返回 typed error。
- [ ] 筛选在稳定分页前执行，计数和页数据共享读快照；cursor 绑定 workspace/query/index generation 与快照，外部编辑后旧 cursor 不可混用。
- [ ] 默认 fast sync 后读取；`--no-sync` 或恢复阻塞时准确报告 generation/index completeness，不把旧索引描述为完整最新状态。
- [ ] Schema discovery 复用当前合并后的 Schema，包含继承后的有效字段和 relation endpoint 约束；没有模型/key 或 Web 时命令仍可使用。
- [ ] 真实 SQLite 与 CLI fixtures 覆盖同名、alias/名称约定、筛选分页、外部编辑、Schema 错误及 descriptor 完整性。

## Blocked by

None (ready after approved shared baseline).

## Scope and handoff

Knowledge read capability 与 Schema discovery 分别保留自身验证职责。复用已有 Node projection、Schema loader、Source read 的同步/分页模式；共享热点是只读 port、registry、CLI 和依赖组装。停止于可发现、可读取的 Node/类型契约；Claim/Evidence 详情归 P05，图遍历及 `node.related` 归 P07/P08，Web Inspector 另行接入。
