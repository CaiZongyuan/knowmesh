# P25: CLI 日志、全局 timeout、trace 与 no-color

## Parent

[并行交付规格](../spec.md)；原任务 [#30](https://github.com/CaiZongyuan/knowmesh/issues/30)。

## What to build

用户可设置日志等级、全局执行 timeout、trace ID 和禁用颜色。无论成功、失败或超时，机器 stdout 保持可解析，诊断保留可关联的 ID 并遮蔽敏感内容。

## Acceptance criteria

- [ ] 已有公共命令接受并校验 SPEC 全局参数；合法 trace ID 贯穿 Core 用例、adapter 与 envelope，无显式 ID 时生成一次，非法 timeout/log-level/ID 返回 typed error。
- [ ] 使用结构化日志并执行 error/warn/info/debug/trace 等级筛选；JSON stdout 仅含结果，日志走 stderr，`--no-color` 后输出无 ANSI 色彩序列。
- [ ] 全局 timeout 向已有耗时用例/adapter 传播，和局部限制取有效剩余预算；本地受控慢 fetch/query fixtures 可观察及时 typed timeout，而不是只解析参数。
- [ ] 到期尊重写操作安全中断边界，已开始的 canonical transaction 保留可恢复材料，stdout 不伪报成功；Run 的累计执行 timeout 由 P14/P17 负责且可接收同一全局限制。
- [ ] 所有等级，包括 debug/trace，均不输出 fixture API key、完整 source/quote/prompt 或 provider 原始错误体；日志仅保留 ID/hash/count/state/耗时等诊断信息。
- [ ] CLI fixtures 覆盖成功、参数失败、adapter timeout、写失败和格式组合，验证 trace 关联、脱敏、stdout/stderr、退出码；help 与公开契约说明同步。

## Blocked by

None (ready after approved shared baseline).

## Scope and handoff

CLI composition/logging 拥有全局设置到既有用例的传递，业务错误和超时语义仍由 Core 拥有；复用 AppError/wire、source fetch deadline 与 Search query budget。共享热点为全局 CLI 参数、执行 context、provider/fetch adapters，和 P24 约定相邻修改落地顺序。停止于已有操作可观测的全局契约；P14/P17/P20 接入持久 Run 预算与控制，HTTP trace 复用同一语义但由 HTTP ticket 实现。
