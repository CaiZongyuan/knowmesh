# P56 初始化前后均可恢复的显式键回执

## Parent

[并行实施规格](../spec.md)；已关闭基础任务 [#6](https://github.com/CaiZongyuan/knowmesh/issues/6) 仅复用既有初始化与 workspace 加载能力，不重新打开；剩余契约 [#30](https://github.com/CaiZongyuan/knowmesh/issues/30)、[#31](https://github.com/CaiZongyuan/knowmesh/issues/31)。

## What to build

用户为 init 指定显式幂等键，首次执行便固定目标和 workspace 身份；即使配置尚未写出、SQLite 尚不存在或成功响应丢失，后续重试仍能恢复并返回原初始化结果。已存在相同 workspace 时自然返回 no-op 的行为继续保留，但不能用它替代首次结果的持久重放。

## Acceptance criteria

- [ ] init 的 Core Input、descriptor 与 CLI 接受可选 idempotency key，沿用基线非空、256 UTF-8 bytes 和无控制字符的校验规则；无键初始化行为兼容。键在 workspace 创建前按安全解析的目标目录与 operation 区分，结构化指纹覆盖 name、template 及全部实际初始化语义。
- [ ] 目标不存在时先验证最近已存在父目录和目标边界，等价路径不能获得两个并发初始化身份；在首次规范文件替换前，耐久恢复记录绑定目标、键、指纹、预分配 workspace ID、计划内容及原始结果所需字段。该记录的写入和读取不依赖已存在的 workspace 配置或 SQLite 数据库。
- [ ] 相同目标、operation、键和输入的并发或重试沿用同一 workspace ID 和初始化事务；同键不同 name/template/其他语义返回 IDEMPOTENCY_KEY_REUSED。遇到冲突的现有文件、不可写目标或未经验证的路径时，保留用户内容并明确失败。
- [ ] 成功回执在报告成功前持久化；同键重放返回首次结果中的 workspace ID、目标及 created paths，而非重新计算的空 created paths 或当前配置。首次请求针对已有匹配 workspace 时，则持久记录该次实际 no-op 结果，后续同键行为一致。
- [ ] 在配置写出前、任一规范文件替换后、事务完成后和响应返回前退出，都能由 init 重试识别原请求，并与既有 Doctor 恢复流程协作前滚或报告明确外部修改冲突；恢复不分配新 ID、不覆盖后来编辑。已知绑定或未完成初始化存在而回执缺失/损坏时明确失败，不当成新请求。
- [ ] 尚无数据库时保留可发现、可校验的初始化回执；若后续转入 DB-runtime，只有接管记录已耐久提交且可回读后才清理唯一恢复副本，正常 sync/rebuild/runtime 保留不丢键或首次结果。该回执是运行态恢复信息，不写成新的规范知识，也不以派生缓存代替；主动丢弃全部运行态后的历史结果不宣称可恢复。
- [ ] dry-run 不创建目标、锁、恢复记录或键绑定，失败预检不消耗键；真实 CLI/subprocess fixtures 覆盖三个内置 template、缺配置/缺数据库、等价路径、同键并发、不同输入、原结果重放、损坏记录与上述退出点，并保持现有初始化恢复和 JSON 契约。

## Blocked by

None after approved shared baseline.

## Scope and handoff

本票拥有 init 的显式键输入、初始化前目标身份、首次结果与回执恢复生命周期，复用固定基线的初始化规划、目标预检、文件事务和无配置时的 Doctor 恢复入口。键规则可以复用，Proposal 专属操作白名单和数据库已存在假设不能直接套用。

共享热点是 Init Input/Report、CLI 与 Operation metadata、目标锁和恢复日志、运行态接管以及架构规则；初始化回执的新增生命周期需同步到已有事务和数据分类说明。与 P27 协调故障点，与 P55 协调维护回执约定，但两票不互相等待才能验证自身公共操作。P54 核验最终初始化重放；不新增模板、历史格式、初始化 HTTP 或隐式自动修复许可。
