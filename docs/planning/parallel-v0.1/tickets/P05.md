# P05: Claim、Relation 与 Evidence 读取闭环

## Parent

[并行交付规格](../spec.md)；原任务 [#31](https://github.com/CaiZongyuan/knowmesh/issues/31)。

## What to build

从 Search hit、Node 或 Relation ID 出发，用户可读取主张和关系、列出其证据，再取得原始 quote、locator 和不可变 Source Revision 身份。该读取契约也是后续 Evidence bundle 的输入基础。

## Acceptance criteria

- [ ] `claim.get/list`、`relation.get/list`、`evidence.get` 使用 Core DTO、registry 和 CLI；detail 保留 qualifiers、生命周期、证据状态、Evidence 引用及适用 conflict group。
- [ ] 列表的 Node、predicate、lifecycle/evidence status 等声明筛选先于 limit；页、计数与相关依赖来自同一 SQLite 读快照，cursor 校验 workspace/query/generation/hash。
- [ ] Evidence detail 返回完整 quote、locator、Source/Revision ID；来源更新或 soft-remove 后历史证据仍可读取，并可通过已有 Source content 命令定位相同 revision。
- [ ] Claim/Relation detail 和列表按既有规则返回 freshness/reasons、全部 evidence_ids 与 current_evidence_ids；独立来源的支持仍保留，缺失或未完整同步依赖显示 unknown。
- [ ] 默认 fast sync，`--no-sync` 和待恢复事务准确披露完整性；不存在 ID、跨类型 ID、坏 cursor 及不可读取依赖返回 typed error。
- [ ] 真实 SQLite/CLI fixtures 覆盖两来源支持、来源换版/移除、closed conflict group、外部编辑和分页；交付供 P19 批量解析的只读契约，防止按单条命令反复拼接混合快照。

## Blocked by

None (ready after approved shared baseline).

## Scope and handoff

Assertion/Evidence read capability 拥有一致快照与引用读取；复用已有 canonical projections、freshness evaluator、source content 和 conflict groups。与 P19 约定批量输入及快照身份；共享热点为只读 ports、registry、CLI。停止于证据可追溯的读取；原文重新验证的 Doctor 集成归 P27，bundle 选择和模型回答归 P19/P20，不新增知识写入路径。
