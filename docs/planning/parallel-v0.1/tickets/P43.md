# P43 从 Web 提问并审核保存 Synthesis

## Parent

[并行交付计划](../spec.md)；原任务 [#34](https://github.com/CaiZongyuan/knowmesh/issues/34)、[#36](https://github.com/CaiZongyuan/knowmesh/issues/36)、[#40](https://github.com/CaiZongyuan/knowmesh/issues/40)、[#41](https://github.com/CaiZongyuan/knowmesh/issues/41)。

## What to build

用户在工作区 Ask 栏提交研究问题，查看可追溯回答及冲突、知识缺口，并将该 Run 的结果保存为待审核 Synthesis Proposal。交付 Ask/Synthesis HTTP、生成客户端和 Web 浏览保存闭环，直接复用既有 Ask 与 Synthesis Core。

## Acceptance criteria

- [ ] Ask HTTP 在 Run 持久化并被执行器接纳后返回 202；输入、预算、幂等、暂停/取消/恢复和结果读取复用 P41 与既有 Ask 执行规则。
- [ ] 工作区 Ask 栏提交问题及明确预算，回答视图同时呈现 Answer、Evidence、Relevant Knowledge、Graph、Conflicts 和 Gaps；partial、omitted、freshness 和来源占比例外不得隐藏。
- [ ] 引用导航只展示最终答案中已通过 Core 验证的 Evidence，并可打开固定 revision 上下文；Markdown 与模型文本作为不可信内容安全渲染。
- [ ] 刷新、重连或重开页面后可读取同一 Ask Run 与终态回答，不重复生成；失败及恢复动作以服务端 allowed_actions 为准。
- [ ] Save synthesis 仅调用 `synthesis.propose`，使用原 Ask Run 的依赖快照并进入 P38 审核；保存和网络重试不直接修改规范知识或重新运行 Ask。
- [ ] 接通 P06 的 synthesis.list/get HTTP 与读取页面，经审核 Apply 后可从列表或搜索再次打开结果，查看引用和 freshness；来源变化后的旧 Synthesis 保留原证据，不静默改成最新回答。
- [ ] 浏览器完整流程覆盖 Ask→引用→Graph→保存→审核→Apply→再读取，以及预算 partial、断线与来源变更；OpenAPI 和生成客户端无漂移。

## Scope and handoff

本票拥有已有 Ask/Synthesis 能力的 HTTP 与 Web 使用闭环，明确包含 synthesis.propose/list/get 的 HTTP 契约和测试。前置输入是 P21 及其 Ask 依赖的稳定输出、P06 读取 DTO、P38 审核入口、P39 图谱导航和 P41 Run 语义。无需等待完整 CLI umbrella、六个 Skills、P40 布局优化或 P42 Source 编译 UI。

共享热点是 Ask/Synthesis 路由、OpenAPI 与生成客户端、全局命令栏、Run Query、回答/Inspector 和缓存失效。优先复用已合并组件；并行 P42 尚未交付时只建立本票需要的最小 Run 展示，不临时互相增加硬依赖。真实回答支持性评测和产品 dogfooding 仍由评测票完成。
