# P10: 可缓存的 Compiler 候选抽取

## Parent

[并行交付规格](../spec.md)；原任务 [#28](https://github.com/CaiZongyuan/knowmesh/issues/28)。

## What to build

固定 Source Revision 经现有 parse/chunk 与受 Schema 约束的模型调用后，产生可验证、可缓存的候选实体、主张、关系和 warnings。后续规划器取得真实候选产物，不需要自行构造模型输出或重复定义 prompt。

## Acceptance criteria

- [ ] Core Compiler 用例接收固定 revision、Schema、Purpose、mode/focus/language 和 provider profile，复用实际 Source bytes、parser/chunker；不可编译来源在发送模型前失败。
- [ ] 使用版本化 compiler prompt 和 Schemars 输入/闭合输出契约；来源仅作为 data，要求逐字 quote/locator、原子 Claim、推断区分和缺证 warning，模型不能输出可执行文件 patch。
- [ ] 候选临时 ID 唯一，subject/source/target 引用闭合，类型、predicate、qualifiers、confidence 和集合规模满足声明边界；跨 Chunk 汇总后的引用仍可验证，坏候选不会成为已接受知识。
- [ ] Candidate cache 绑定实际 blocks/hash、revision、prompt、Schema、Purpose、provider/model/profile/sampling；相同有效产物避免重复请求，依赖变化或完整性损坏导致适当 miss。
- [ ] 成功和失败均保留脱敏 diagnostics、usage 与产物身份；repair/retry 复用已有 model generation 上限，不另设绕过预算的重试循环。
- [ ] 可执行 Core 集成测试使用真实 parser/cache 和 fake provider，从来源 bytes 走到候选产物；覆盖注入文本、错误引用、schema-invalid 输出、repair、quality gate 与缓存失效，canonical 字节和 Proposal runtime 不变。

## Blocked by

None (ready after approved shared baseline).

## Scope and handoff

Compiler 拥有抽取 prompt、候选 DTO 和临时引用语义；复用基线 SourceParser、chunker、FileStageCache、ModelProvider 与 structured generation。共享热点是候选 stage identity 和模型调用契约，须与 P14 的逐请求控制兼容。此票通过最高 Core 用例的可执行集成测试验收，不新增临时 CLI 或公开 registry entry；P11/P12 负责 Evidence/知识规划，P15 才交付公开 source.compile 与 durable Run。停止于完整候选产物。
