# P09: Source Chunk 检索投影与重建再生

## Parent

[并行交付规格](../spec.md)；原任务 [#31](https://github.com/CaiZongyuan/knowmesh/issues/31)、[#42](https://github.com/CaiZongyuan/knowmesh/issues/42)；复用已关闭 [#22](https://github.com/CaiZongyuan/knowmesh/issues/22) 的 chunk/cache 能力。

## What to build

导入来源并同步后，即使尚未形成 accepted assertions，用户也能通过已有 Search 找到可解析的原始 Chunk。删除派生索引后，同一来源和解析配置能重建相同的 Chunk 搜索内容。

## Acceptance criteria

- [ ] `source add` 后执行现有同步/检索流程，符合质量门的 Markdown/TXT/HTML/PDF 来源产生实际 Chunk projection 与 search units；CLI Search 返回 revision、定位区间、preview 和 owner。
- [ ] 复用 parser/chunker/cache 验证，保持 normalized spans、结构边界和确定性 Chunk 身份；质量门失败按明确结果跳过不可编译文本，不把损坏产物索引为成功。
- [ ] 来源 revision、parser/chunker 配置或完整产物变化时更新对应派生映射；移除/历史来源遵循既有 Search filters，已接受 Evidence 的身份与 locator 保持不变。
- [ ] 删除或损坏缓存后，sync/rebuild 能从可验证原始 bytes 再生 Chunk；rebuild 保留 runtime，失败时原完整索引仍可读取且错误原因可见。
- [ ] Chunk 写入受既有 projection 边界和同步事务协调；索引完整性、查询 cursor 与实际 Chunk 配置一致，不暴露半批索引结果。
- [ ] 真实 CLI/SQLite fixtures 覆盖导入到 lexical hit、source filters、cache miss、换版、quality gate 和删除 DB 后重建；没有模型/key/vector 时流程通过。

## Blocked by

None (ready after approved shared baseline).

## Scope and handoff

Ingest 产物与 projection 协调共同拥有 Chunk 索引，复用 `5247efe` 的 Source bytes、cached parse/chunk 和 Search filtering。共享热点为同步/rebuild、projection writer 登记、search units 与完整性标识；这属于派生写入，不给 Compiler canonical 写能力。交付 Chunk 到 Search/rebuild 即停止；P22/P23 负责 embedding/vector，P10–P15 负责 Compiler，P19 仍只允许真实 Evidence 进入回答。
