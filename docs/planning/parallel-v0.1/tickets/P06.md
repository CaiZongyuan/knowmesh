# P06: Synthesis get/list 与派生 freshness

## Parent

[并行交付规格](../spec.md)；原任务 [#31](https://github.com/CaiZongyuan/knowmesh/issues/31)。

## What to build

用户可列出和读取现有规范 Synthesis，包括正文、引用及生成时依赖快照，并识别来源或主张变化后的复核需求。

## Acceptance criteria

- [ ] `synthesis.get/list` 提供 Core DTO、Operation descriptors 和 CLI；detail 包含正文、Evidence/Node 引用、已有 dependency snapshot，列表仅含有界摘要。
- [ ] 列表有确定排序、有界 limit 和 continuation，计数与当前页来自一致 SQLite 快照；跨 workspace/query 或 stale cursor 被拒绝。
- [ ] freshness 复用已实现规则，来源 head 或 assertion 语义改变产生可解释原因；仅标题/排版改变不伪造语义变化，历史缺少快照时显示 unknown。
- [ ] 默认 fast sync；`--no-sync`、待恢复事务或依赖缺失不返回 current，读取不会用当前索引补写历史快照或修改规范正文。
- [ ] CLI 和真实 rebuild fixtures 证明 Synthesis 内容、引用和 freshness 可重建，空列表、不存在 ID、旧人工文件与新快照文件均有明确结果。

## Blocked by

None (ready after approved shared baseline).

## Scope and handoff

Synthesis read capability 复用基线 parser/writer、projection 和 freshness；仅扩展只读 port、registry、CLI 与组装，不重做已完成的 #10 parser。停止于现有 Synthesis 的读取；生成 Ask、创建新 Synthesis Proposal 和保存闭环由 P20/P21 负责，Web 页面另行消费同一 DTO。
