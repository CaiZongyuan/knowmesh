# P41 通过 HTTP 接纳并控制可恢复编译任务

## Parent

[并行交付计划](../spec.md)；原任务 [#28](https://github.com/CaiZongyuan/knowmesh/issues/28)、[#34](https://github.com/CaiZongyuan/knowmesh/issues/34)。

## What to build

调用方通过 HTTP 提交编译后立即获得已接纳的 Run，随后读取进度、控制暂停或取消，并显式恢复原任务。复用 P17 的完整执行器，证明浏览器连接生命周期与本地任务生命周期相互独立；此票可以完全通过 HTTP 验收。

## Acceptance criteria

- [ ] compile/resume 只有在 Run 输入已持久化且被本进程执行器接纳后才返回 202 与 Run DTO；接纳失败返回真实错误，不留下伪装成已执行的成功响应。
- [ ] list/get 返回有界摘要、stage/progress、attempt、控制请求、累计预算、allowed_actions 和终态输出；纯读取不修复状态、不重新领取任务。
- [ ] 同幂等键重复提交观察同一 Run；浏览器断连、请求超时或页面刷新不取消任务，也不触发第二次模型调用或结果发布。
- [ ] pause/cancel 返回 200 与真实 Run/control_action，仅确认请求已登记时不得宣称已停止；取消后的迟到成功不能发布 Proposal。
- [ ] resume 复用原 Run、checkpoint 和预算，并校验 allowed_actions、依赖及执行所有权；CLI 与 HTTP 同时争抢时最多一个有效 attempt。
- [ ] Server 重启不自动执行遗留 queued/interrupted Run；读取提示失联，显式恢复按原有 Core 规则执行，不重置预算或静默替换输入。
- [ ] fake provider 的真实 HTTP 测试覆盖响应丢失、断连、并发 resume、控制期间迟到结果和终态输出；OpenAPI、Operation 覆盖及可用时的生成客户端随契约同步。

## Scope and handoff

本票拥有 HTTP 异步接纳、控制和结果读取，不重新实现 Run 状态机、预算或 Compiler。前置输入是 P17 已验证的执行器接口与 Run DTO，以及 P32 的认证和 Server 生命周期；同步 Core 的阻塞工作不得阻塞服务对控制请求的响应。

共享热点是 Server 组装与生命周期、Run/compile 路由、Operation registry、OpenAPI 和架构规则。P33 不是硬依赖：生成客户端尚未存在时交付可生成的 OpenAPI；已存在时按写入窗口更新快照与生成物。P42 负责 Source UI，P43 接入 Ask；本票不引入独立 daemon、队列服务或自动任务恢复策略。
