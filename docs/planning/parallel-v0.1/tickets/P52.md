# P52 检索相关性与公开容量性能评测

## Parent

[并行实施规格](../spec.md)；原始需求 [#42](https://github.com/CaiZongyuan/knowmesh/issues/42)。

## What to build

在可追溯研究材料与明确标识的容量 fixture 上比较 word、trigram、vector、hybrid 检索质量，并测量公共 CLI、Graph 和同步性能。保留无 boost 基线，让公开容量和延迟目标对应到真实报告。

## Acceptance criteria

- [ ] 查询集覆盖中文、英文、中英混合、缩写、Gene symbol、别名、两字中文和精确 ID；相关性判断具有人工审核记录和材料版本，未审核判断不得作为已验证质量结论。
- [ ] 使用同一固定评测集合比较 word-only、trigram-only、vector-only、hybrid 的 MRR、Recall@5/10、nDCG@10 与 latency，同时报告无 boost 基线、实际通道和配置；向量不可用时记录未验证或降级结果。
- [ ] 排名回归覆盖 raw/normalized/boost 尺度、从 1 开始的 rank、空或失败通道、单通道降级、精确 ID 与 filters、alias/prefix boost、候选池截断和 cursor stale。
- [ ] 报告参考机器、OS、构建版本、数据规模、冷热状态、采样次数和分位数；质量语料与合成容量数据分别标识，外部模型网络延迟与本地检索延迟分开计量。
- [ ] 在公开支持规模下测量容量边界与具体目标：20k Node 的 node get p95 小于 100 ms，100k Search Unit 的 lexical p95 小于 200 ms、hybrid p95 小于 1 s，depth-2 neighbors p95 小于 300 ms；同时记录 200k Claim、200k Relation 和响应截断边界的实际覆盖。
- [ ] 测量无 workspace 的 version p95 小于 100 ms，以及 10k canonical files 无变化 fast sync 小于 2 s；未达标或未完成的规模保留原指标，明确失败、瓶颈和未验证项。
- [ ] 结果可复现并固定输入、随机种子或数据生成参数、模型/embedding 配置与成本；结论不以某个名称被置顶代替总体相关性，Web 首屏性能留给 P54 引用对应 UI 验证。

## Scope and handoff

本票拥有检索质量与后端性能报告，复用现有 ranking、cursor、Graph、sync 测试以及 P01 的材料清单。人工相关性审核与真实 embedding 服务可用性是额外就绪条件；性能优化或搜索语义调整交给范围明确的后续修复票。共享 benchmark 数据和口径保持一处，P54 汇总实际达标、失败和未验证状态。
