# P23: Optional sqlite-vec 与过滤后的 RRF 检索

## Parent

[并行交付规格](../spec.md)；原任务 [#18](https://github.com/CaiZongyuan/knowmesh/issues/18)。

## What to build

用户启用 embedding 时，已有 Search 在 lexical 之外使用 sqlite-vec 通道；没有 extension/key/provider 时仍能搜索并明确披露降级。向量 projection 可随 profile 重建，并保留每个 Search Unit 的独立身份。

## Acceptance criteria

- [ ] sqlite-vec 通过 Rust binding 静态注册为 optional capability；有/无 extension 与有/无 key 四种组合均可启动，无向量时既有 lexical Search 和核心命令可用。
- [ ] 使用 P22 已验证产物为适用 Search Units 建立映射，包括 P09 Chunks；跨 revision 复用向量仍为新单位建立独立映射，canonical Markdown 不保存 embedding。
- [ ] 同 workspace 只有一个 active profile；model/dimensions/config 变化触发完整 vector projection 重建，旧 profile 不混入新查询，失败/缺产物的状态可见。
- [ ] Vector 候选在 per-channel limit 前应用与现有 Search 相同的 ownership/source/lifecycle 等过滤，稳定 public IDs 进入既有 weighted RRF、exact-ID tier 和 explain。
- [ ] Core Search DTO/descriptor、CLI envelope 和 status/capability 输出反映实际通道参与；成功空通道、缺失/失败通道和降级保持既有归一化规则，profile/候选/通道变化使旧 cursor 失效。
- [ ] 真实 SQLite/CLI fixtures 覆盖四种启动组合、filters before limit、新 revision 映射、profile/dimension 重建、provider 失败及缓存恢复；保留 no-boost lexical 基线并可运行 vector/hybrid eval。
- [ ] 实体解析的 optional vector top-k 接入同一有效快照，在候选限制前应用 Node type/active 过滤并绑定实际通道/context hash；向量候选仍须审核，完整 catalog 歧义和 Top-2 接近时的保守规则不被覆盖。

## Blocked by

## Scope and handoff

Vector projection/Search capability 拥有映射、通道过滤及降级，复用 P22 embedding、P09 Chunk projection、现有 RRF/cursor 和 entity retrieval。共享热点为 SQLite extension/profile 状态、Search/entity read ports、rebuild、migration registry 和 capability metadata；新增派生 writer 纳入架构门禁。停止于可使用/可降级/可重建的 vector Search 与实体候选接入，不提升自动匹配权限；真实 retrieval/performance 质量仍由 release eval 证明。
