# P15: 前台 compile、checkpoint 与原子 Proposal 发布

## Parent

[并行交付规格](../spec.md)；原任务 [#28](https://github.com/CaiZongyuan/knowmesh/issues/28)、[#31](https://github.com/CaiZongyuan/knowmesh/issues/31)。

## What to build

用户执行 `compile source`，得到持久 Run 和一份待审核 Proposal。真实执行器把已有 Compiler stages、Run 准入和逐请求预算连为完整路径，并在各阶段提交可验证 checkpoint。

## Acceptance criteria

- [ ] `source.compile` 提供完整 Core Input/Output、Operation descriptor 与 CLI；支持 full/entities/assertions、显式 revision 和固定默认 head、profile/预算/幂等 key，默认前台只输出一个最终 JSON envelope。
- [ ] 执行者持有 per-run OS lock，在 SQLite 中比较状态后领取并递增 attempt；同时执行返回 RUN_ALREADY_ACTIVE，模型调用期间不持有 workspace canonical write lock。
- [ ] Parse、chunk/extract、verify、resolve、dedup/conflict、validate/build 均保存完整 stage checkpoint 与已持久化产物引用，调用前保存实际知识输入快照，失败/半成品不标记完成。
- [ ] 请求全部经过 P14 的预算与 attempt/control 检查；结果包括脱敏 diagnostics、累计 usage、output refs 和 typed error，失败后状态可由已有 run.get 查询。
- [ ] 最终 Proposal revision、Run output refs、成功 checkpoint/status 和幂等观察结果在同一 runtime transaction 发布，并核对 attempt/status/control；提交失败不会留下无主 Proposal 或伪成功 Run。
- [ ] 真实 CLI/SQLite + fake provider fixtures 从导入来源走到待审 Proposal，再通过既有 review/apply/search 验证知识闭环；覆盖三种 mode、同 key 重试、并发领取、stage 失败及输出提交后响应丢失，编译自身不改 canonical。

## Blocked by

- [P12: Assertions 与 full 模式的完整 Proposal 规划](P12.md)。
- [P14: 逐模型请求的持久预算、重试与控制接入](P14.md)。

## Scope and handoff

Run 执行器拥有领取、checkpoint 和发布；Compiler 保持阶段规划职责，Proposal store 参与同一最终事务。复用已有 cache artifacts、Builder、runtime copy 与 idempotency；共享热点为 Run port、Proposal transaction、registry/CLI、writer policy。交付公开前台 compile 即停止；P16/P17 补齐完整用户控制和恢复，P18 接入 refresh，HTTP 202 复用此执行器而非另起一套。此票不表示 §20.4 全部验收完成。
