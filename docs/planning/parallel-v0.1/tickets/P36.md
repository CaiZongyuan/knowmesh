# P36 补齐来源规范写入的持久幂等结果

## Parent

[并行交付计划](../spec.md)；历史基础 [#8](https://github.com/CaiZongyuan/knowmesh/issues/8)，剩余契约 [#30](https://github.com/CaiZongyuan/knowmesh/issues/30)、[#31](https://github.com/CaiZongyuan/knowmesh/issues/31)。#8 已关闭，仅引用其已实现的来源存储基础，不重新打开。

## What to build

用户为 source add/remove 指定幂等键后，即使响应丢失、进程中断或再次调用，也能获得同一次已提交来源操作的结果。保留现有同内容 hash 去重与不可变 revision 语义，补齐显式键对应的持久重放契约，并通过 CLI 验证。

## Acceptance criteria

- [ ] source add/remove 接受可选幂等键，Core descriptor 与 CLI 参数准确反映能力；无键调用保留现有行为。
- [ ] 同 workspace、operation、键和规范化输入重试返回首次已提交结果，不额外创建 Source/revision、移动 head 或重复 soft-remove 副作用。
- [ ] 已使用键的请求输入改变时返回 `IDEMPOTENCY_KEY_REUSED`；键绑定规则覆盖本地材料、URL、source_id、storage、encoding 和 remove 输入，不暴露秘密信息。
- [ ] 并发相同请求和提交后响应丢失不会得到两个已接受结果；网络来源重试不能借同一个已完成键导入后来变化的内容。
- [ ] 幂等结果与规范写入/恢复协议协调；故障注入覆盖规范提交与结果记录之间的中断，恢复后只能重放原结果或报告明确冲突。
- [ ] dry-run 不登记已提交幂等结果、不写规范文件；remove 缺确认仍返回原确认错误，不能通过键重放绕过授权检查。
- [ ] 正常 rebuild、runtime 保留与事务恢复后仍可读取有效结果；显式丢弃 runtime 或不可恢复情形的限制有明确契约，CLI shell 测试证明 stdout 与错误 envelope 不受污染。

## Blocked by

None；共享基线合并后可开始。

## Scope and handoff

本票拥有来源写入的键绑定、持久结果、恢复与 CLI 接入。前置输入是已实现的 Source manifest/revision、来源事务和 Proposal 幂等的验证经验；不能把 Proposal 专属记录结构直接当作来源契约，也不能更改历史 revision 的身份。

共享热点是 Source Input/Report、Operation metadata、CLI source 参数、runtime 存储/迁移、事务恢复登记与架构规则。先明确输入指纹及恢复后的结果归属，再实现；迁移编号与其他存储票协商。P37 仅复用本票已落地的 Core 幂等能力；通用 CLI 格式、完整命令树和 HTTP 均不属于本票。
