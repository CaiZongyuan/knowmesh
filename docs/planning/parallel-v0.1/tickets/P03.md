# P03: Relaxed accept-all 与 Apply 组合操作

## Parent

[并行交付规格](../spec.md)；原任务 [#27](https://github.com/CaiZongyuan/knowmesh/issues/27)。

## What to build

在 workspace policy 允许时，用户可用显式确认的组合入口接受尚未决定的 Proposal items 并 Apply。入口复用已有审核、接受子集重验证和恢复事务，保留第一次执行及重试的可观察结果。

## Acceptance criteria

- [ ] Core 输入与 descriptor 明确组合语义，CLI 参数映射同一用例；用户无需分别调用 review 和 apply 即可完成允许的 relaxed Proposal。
- [ ] Bulk 仅处理 pending items，保留既有 rejected 决定；strict、禁止 accept-all、需要 human verification 或 blocking issue 时按实际 Schema policy 拒绝。
- [ ] dry-run 只返回接受子集的真实预览，不写审核/runtime/canonical；执行缺少确认时无副作用，stale revision/generation/before hash 仍阻止 Apply。
- [ ] 组合流程复用已有幂等键与 Apply receipt，明确绑定整个请求；相同 key 重试返回原结果，不同输入拒绝，在审核成功或文件事务中断后重试不会重复接受或重复写文件。
- [ ] SQLite 与 CLI fixtures 覆盖部分拒绝、全部拒绝、strict policy、dry-run、缺少确认、审核后失败恢复及成功后响应丢失；原有 Apply journal 和 actor 信息保留。

## Blocked by

None (ready after approved shared baseline).

## Scope and handoff

Proposal workflow 拥有组合协调；复用 `5247efe` 已完成的审核 hash、Builder、accepted preview、Apply transaction 和 idempotency receipt。共享热点为 Proposal workflow/CLI 输入与 registry；如需扩展键语义，保持已有单命令重放兼容。停止于安全可重试的便利入口；P02 列表、Compiler 自动运行及 Web 控件另有归属。
