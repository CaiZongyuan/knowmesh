# P20: 持久且有证据约束的 Ask

## Parent

[并行交付规格](../spec.md)；原任务 [#40](https://github.com/CaiZongyuan/knowmesh/issues/40)。

## What to build

用户运行 `ask`，得到由本次 Evidence bundle 支持的 Answer、citations、conflicts、gaps 和相关知识图。结果与生成时 manifest 保存到可控制、可恢复的 Run，未保存时不写规范知识。

## Acceptance criteria

- [ ] `knowledge.ask` 提供 Core Input/Output、descriptor、幂等 key 和前台 CLI，包含 SPEC 的 sources/evidence/share/tokens/cost/timeout budgets，正常执行只输出一个最终 envelope。
- [ ] 版本化 synthesis prompt 和闭合 structured output 只使用 P19 实际 bundle；解析全部引用，未知 ID 或虽存在 DB 但被移出 bundle 的 ID 阻止最终回答发布。
- [ ] 事实性输出单元需要 Evidence 引用，跨证据推断进入 inferences 并有语言标识；冲突双方缺失、证据不足、freshness needs_review/unknown 和 bundle 截断均在结果中披露。
- [ ] 回答包含 citations 的 Source/Revision/locator、relevant_nodes、retrieval manifest、conflicts 和 knowledge_gaps；相关 graph 复用 P07 的有界 Graph DTO/查询与过滤、截断语义，原始 Chunk-only 结果不冒充有证据答案。
- [ ] 复用 P17 同一执行器和 P14 逐请求累计预算；Answer、bundle/敏感产物引用、dependency snapshot、output refs 与成功 checkpoint 原子发布，pause/cancel/resume 和晚到结果遵循相同 Run 规则。
- [ ] 预算停止能形成合法部分结果时标记 meta.partial 与停止原因，否则返回诚实 gap/typed error；真实 CLI/SQLite + fake provider fixtures 验证引用伪造、冲突、预算、同 key 重试、崩溃恢复及无 canonical 写入。

## Scope and handoff

Ask 拥有回答 Schema、prompt 和引用校验；Run 统一拥有执行/预算/发布，Graph 由 P07 提供有界结果，复用已有 structured generation，不新增专属 executor 或平行图算法。共享热点为 Run output variants、Graph DTO、敏感 artifacts、Operation registry/CLI 和 manifest Schema。停止于可读、可恢复的 Ask result；P21 负责保存 Synthesis，HTTP/Web 复用此 operation。合法 ID 只证明可追溯，事实支持程度与十个真实研究问题的人评仍属于 release eval。
