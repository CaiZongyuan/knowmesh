# P33 交付独立 Web 状态页与兼容性握手

## Parent

[并行交付计划](../spec.md)；原任务 [#2](https://github.com/CaiZongyuan/knowmesh/issues/2)、[#35](https://github.com/CaiZongyuan/knowmesh/issues/35)、[#36](https://github.com/CaiZongyuan/knowmesh/issues/36)。

## What to build

建立独立构建的 Web 客户端，首屏实际连接后端并显示 workspace 状态。完成后续页面使用的路由、响应式工作区、生成客户端和兼容性握手；只建立最小可运行界面，不把未来页面占位当作功能交付。

## Acceptance criteria

- [ ] Web 使用 SPEC 指定的前端技术栈和固定依赖，可以独立完成类型检查、测试和构建；Rust 检查不需要运行前端工具链。
- [ ] 状态页通过生成客户端读取真实 capabilities/status；页面显示实际 workspace 与连接状态，不能以固定演示数据替代成功响应。
- [ ] 首次连接先验证 API contract range 和当前页面必需能力；版本字段缺失、不兼容或缺少必要能力时显示明确状态，并阻止业务查询与 mutation。
- [ ] API 不可达时可重试，连接恢复后重新握手；可选能力缺失只影响对应功能，不错误阻止可用状态页。
- [ ] 工作区布局、导航和 Inspector 在桌面及移动视口可用，键盘可以到达实际功能；URL、服务器缓存与临时 UI 状态按 SPEC 分工。
- [ ] TypeScript、Zod 和 Query 生成物来自后端 OpenAPI 快照，无人工补丁；生成漂移检查可发现未提交契约变化，Web 构建不要求运行后端。
- [ ] 浏览器测试覆盖真实状态响应、加载失败、版本不兼容和断线重连；本票不宣称 Search、Graph 或 Ask 已交付。

## Blocked by

- [P32 API-only Server](P32.md)

## Scope and handoff

本票拥有前端基础工程、最小状态页和客户端生成流程。前置输入是 P32 已合并的基础 OpenAPI、错误 envelope、认证方式和能力说明；初始页面不能强制要求尚未实现的 graph 能力。

本票集中拥有首次前端依赖清单、锁文件、工作区配置、共享路由与契约生成设置。交付时记录生成命令、快照来源和浏览器连接方式。后续纵向票自行更新对应 OpenAPI 与生成客户端，并在共享生成物写入窗口串行再生成；不要求本票提前生成完整 API，也不负责 Web 发布或外部静态托管。
